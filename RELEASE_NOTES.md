## [3.7.17] - 2026-09-10

**Создание артефакта больше не считает номер.** Второй шаг полосы: механизм
3.7.16 включён в продукт — десять создающих скиллов чеканят семя, а номер по-
прежнему выдаёт только транк.

### Что изменилось в командах

`/polisade:tasks`, `/polisade:spec`, `/polisade:roadmap`, `/polisade:prd`,
`/polisade:design`, `/polisade:defect`, `/polisade:debt`, `/polisade:chore`,
`/polisade:feature`, `/polisade:spike` — все берут семя вместо номера:

| Было | Стало |
|---|---|
| прочитать счётчик и три источника, взять `max(...) + 1` | `polisade_id.py new-seed` |
| **Counter drift → АБОРТ**, ни одного файла до устранения | дрейфовать нечему: номера при создании нет |
| write-guard сверял будущий номер с `artifactIndex` | сверять нечем — проверяется только существование файла |
| инкремент счётчика после записи | счётчик пишет транк |

Круг ревью показал, что первая редакция флипа была **неполной**: шаг «вычисли
номер» я заменил, а ниже по тексту девять команд продолжали писать `FEAT-{N}`,
искать `{N}` в `artifactIndex` и «инкрементировать `DESIGN`». Скилл взял бы семя
и подставил его в шаблон, где нет `seed:`, — а такой артефакт sync отказывается
нумеровать. Исправлено во всех местах, и нога теперь читает **собранные** тела,
а не только исходники.

Скиллы стали **короче**. У пакетного `/polisade:tasks` исчез целый режим: не
стало «после первого `next_id` присваивай `+1, +2` без повторного чтения диска»
— у каждой задачи своё семя, последовательности нет, и ссылаться друг на друга
внутри пачки можно сразу через `depends_on: [TASK-<семя соседа>]`.

### Машинные ссылки едут за номером, проза — нет

`parent:`, `depends_on:`, `blocks:`, `related:`, `realizes_requirements:` несут
id **других** артефактов, и их сравнивают с id, а не читают глазами. Поэтому при
нумерации sync переводит их на новый номер — включая составные формы вроде
`SPEC-<семя>.FR-001`. Совпадение только по целому токену: `TASK-a1b2c3d4x` не
трогается, когда номер получает `TASK-a1b2c3d4`.

Список читается в **обеих** формах YAML. Шаблоны отгружают инлайновую
(`depends_on: [A, B]`), и первая редакция видела только её — написанный руками
блочный список молча остался бы указывать на несуществующий id. Отдельно закрыта
**ноль-отступная** форма, где элементы стоят в той же колонке, что и ключ: её
пропускают чаще всего, и ровно ею оказался BUG-008 в Reverse.

**Проза остаётся с семенем** — и это не недоделка, а причина, по которой семя
постоянно. Текст человека верен ровно потому, что семя не двигалось, а
`polisade_id.py resolve <семя>` читает его и через год.

### Правило, объяснённое неверной причиной

`/polisade:implement` запрещал субагенту создавать артефакты словами
«`counters.json` недоступен». С семенами это перестало быть правдой: создать
артефакт в worktree технически можно. Запрет остаётся — но причина у него
другая и всегда была другой: субагент исполняет выданную задачу, а решение
завести новую работу принимает PM. Правило, которое держится на неверной
причине, приглашает его нарушить, как только читатель эту причину проверит.

### Первая задача свежего проекта — снова `TASK-001`

Поправка приехала в 3.7.16 и здесь становится видимой: шаблон счётчиков отгружал
`1`, а весь код читает счётчик как «последний использованный», поэтому первая
задача нового проекта получала `TASK-002`, а `TASK-001` не использовался
никогда.

## [3.7.16] - 2026-09-10

**Номер артефакта перестал выдаваться на ноутбуке.** Первый шаг полосы: у
артефакта появилась постоянная опознавалка, а выдача номеров переехала в
единственное место, где она не может столкнуться сама с собой.

### Две фазы: семя где угодно, номер на транке

Номер из `.state/counters.json` — это догадка конкретного клона. Протокол
требует держать счётчик монотонным «даже если артефакты удалены», то есть он
несёт отметку над УДАЛЁННЫМИ артефактами, которой нет ни в одном закоммиченном
файле. Замер на репозитории, где `TASK-004` создали и удалили: у автора
следующий номер `005`, на свежем клоне коллеги — `004`. Двое создают `TASK-005`
дважды, и ни одна машина об этом не узнает.

Теперь у артефакта два имени:

* **семя** чеканится при создании, на любой машине и любой ветке
  (`polisade_id.py new-seed`), живёт в `seed:` и **не меняется никогда**;
* **номер** выдаёт `/polisade:sync --apply`, запущенный **на транке**, и только
  там. Одно место не может столкнуться само с собой.

На транке файл переименовывается (`TASK-k7m2q4xz-slug.md` → `TASK-007-slug.md`),
`id:` переписывается, `seed:` остаётся. Вне транка не нумеруется ничего, и отчёт
**говорит почему** — вместе со списком того, что было бы выдано: молчаливый
no-op читался бы как «нумеровать было нечего».

### Почему это ничего не сломало

Первый символ семени — буква. Значит `stem.split("-")[1].isdigit()` на нём
ложь, а `^SPEC-(\d+)` не матчится: **ненумерованный артефакт невидим для
счётчика по построению**, и ни одна из двенадцати формул протокола не менялась.
Схема аддитивна не по договорённости, а по устройству формата — и регрессия
проверяет это на двадцати тысячах свежих семян, а не на одном примере.

Замер вскрыл и то, что чуть не стало дефектом: **`git mv` отказывается двигать
неотслеживаемый файл** (`fatal: not under version control`), а артефакт,
созданный прямо на транке и ещё не закоммиченный, — именно такой.
Переименование поэтому двухветочное: `git mv` там, где git видит файл (история
переживает переименование), обычный `rename` там, где нет.

### Семя остаётся навсегда — иначе ссылку не прочитать

Ссылку, сделанную ДО нумерации — сообщение коммита, заголовок PR, строку в
переписке, — переписать нельзя. `polisade_id.py resolve <семя>` отвечает на неё
и через год, печатая текущий `id` и путь. По той же причине sync **не трогает
прозу** внутри артефактов: текст остаётся верным ровно потому, что семя не
двигалось.

`/polisade:doctor` докладывает `seed_identity`: сколько артефактов ещё под
семенем (на ветке это норма — важно, чтобы человек прочитал ответ, а не гадал),
и **падает** на трёх формах, где семя перестаёт работать: одно семя на двух
артефактах, отсутствующее `seed:` при семенном `id`, и `seed:`, не совпадающий
с хвостом `id`. Все три выглядят исправно, и во всех трёх теряется ровно та
ссылка, ради которой семя и живёт. Sync такие артефакты **не нумерует**:
выдача номера — необратимая половина, и делать её до того, как ссылка станет
разрешимой, нельзя. Копирование файла артефакта — обычный способ устроить
первую форму, и больше никто бы не заметил.

**Граница схемы названа честно.** «Одно место» — это один транк *в одной
истории*. Два клона, оба на транке, оба выдавшие номер до того, как кто-то
запушил, всё ещё получат одинаковый номер. Разница в том, что теперь это
**чинится**: идентичность живёт в семени, поэтому перенумерование безопасно, а
столкновение видно — после `pull` следующий sync упирается в `duplicate_ids` и
называет оба файла. До семени такое столкновение было тихим и неисправимым.

Счётчик при этом не выброшен, а понижен в должности: он **пол**, с которого
начинается нумерация на транке. Это его единственная незаменимая работа — на
диске нигде не записано, что `TASK-004` когда-то был, и без пола удалённый
номер выдался бы второй раз, а старая ссылка в истории git начала бы указывать
на другую работу.

### ⚠️ Поправка к нотам 3.7.15 — «одна редакция» сказано слишком сильно

Запись 3.7.15 утверждает, что правило в `tools/convert.py` и публикационный
сторож дают **один вердикт**, и что регрессия сравнивает вердикты обоих. Верно
только про шаблон. Решение сторожа — это регулярка **плюс список имён-заглушек**
(`user`, `test`, `example`, `foo`, `bar`, `baz`, `demo`, `runner`, `USERNAME`),
применяемый после неё; в сборке такого списка нет.

Замерено прогоном настоящего сканера: расхождение — это **ровно** список
заглушек и ничего кроме, и оно **всегда в одну сторону: сборка строже**.
`/Users/user/x`, `/Users/test/x` и все остальные имена из списка сборка
отклоняет, а зеркало пропускает. Это безопасная сторона: путь с машины не должен
попасть в поставляемую команду оттого, что владельца зовут `test`. Обратное
направление — то, ради которого правило и переписано: ни одна форма, которую
пометит зеркало, не проходит сборку.

Нога берёт список **у самого сторожа**, а не переписывает его: имя, добавленное
туда, появится в проверке на следующем прогоне, и утверждение «расхождение —
это ровно заглушки» перестанет быть прозой.

Свойство поэтому **вложение, а не равенство**, и нога проверяет именно его —
прогоном настоящего сторожа, а не сравнением двух регулярок. Верным в записи
3.7.15 остаётся главное: сегмент имени пользователя написан тем же символьным
классом (это и сняло ложное срабатывание на многоточии), приватное имя из файла
исчезло, проверка тел доехала до сборки Qwen/GigaCode.

## [3.7.15] - 2026-09-10

**Три решения PM, доведённые до кода.** Полоса мелкая по объёму и закрывает
вопросы, которые до сих пор оставались открытыми в справочнике или жили как
ручной ритуал.

### База приёмки ездит с репозиторием

`.state/acceptance-baseline.json` записывает, **что было ратифицировано**:
дайджест каждой пары приёмки И дайджесты приборов — тест-файлов, которые
запускает чек. Правка тест-файла — второй способ купить зелень, и ни одна из
половин не выводится из текущего дерева, потому что база и есть то, **с чем**
дерево сравнивают.

Пока файл был локальным, ничего не зеленело молча: `--fail-on-changed` без базы
отказывается, а не проходит. Не хватало другого — ослабленный чек видел только
тот, кто последним прогонял приёмку у себя; коллеге и CI сравнивать было не с
чем. Теперь файл возвращается шаблоном `.gitignore`, а существующим проектам его
добавляет `/polisade:migrate` — сразу после возврата `knowledge.json`.

Позиция проверяется, а не наследуется. В git побеждает **последнее** совпавшее
правило, поэтому две формы `.gitignore` делают возврат недостижимым: отрицание
выше своего исключения и `.state/` где-нибудь ниже. Мигратор уже отказывался
чинить их для `knowledge.json`; первая редакция этой правки унаследовала место,
но не проверку — и писала мёртвую строку, объявляя её починкой. Теперь в обеих
формах файл не трогается: порядок правил там — решение человека, и спрашивают о
нём один раз, а не дважды.

Попутно закрыты два дефекта того же слоя, оба воспроизведены на живом git.
**Отступ убивает правило:** ведущие пробелы — часть шаблона, `!` отрицает,
только когда стоит первым символом, поэтому `  !.state/knowledge.json` не
возвращает ничего. Мигратор считал такую строку рабочей с самой починки возврата
`knowledge.json` и объявлял починку, которой не было; теперь обе миграции
смотрят на нулевую колонку.
**Файл без завершающего перевода строки** склеивал два правила в одно
(`…knowledge.json!.state/acceptance-baseline.json`) и уничтожал оба — видно
только в уже мигрированном проекте, где соседняя миграция не дописывает конец
файла за нас. Новая строка теперь наследует окончание самого файла, включая
одиночный CR.

Конфликты здесь редкие и осмысленные: файл двигается, только когда человек
**сознательно** переподтверждает проверки, а двое, переподтвердившие разное, —
ровно то, что надо увидеть.

### Версия поднимается одной командой

Релизный ритуал двигал **восемь** механических утверждений о версии вручную, и
именно это позволило строке покрытия в справочнике отстать на двенадцать
патч-релизов при всех зелёных воротах. `scripts/polisade_bump_version.py 3.7.15`
двигает все восемь разом (этим релизом он и поднят — самопроверка).

Инструмент **отказывается**, а не угадывает, в четырёх случаях: дерево уже
рассогласовано (переписать его значило бы стереть улику), версия ниже текущей
без явного флага, источник перестал совпадать со своим шаблоном **или совпал
дважды** — молчаливый пропуск и есть тот дрейф, ради которого команда написана,
а из двух совпадений она подвинула бы первое и его же прочитала обратно, — и
правка задевает больше одной строки в файле. Последнее ловит переформатирование: собственная
проба нашла, что чтение с переводом переносов молча меняло CRLF на LF во всём
файле, а проверка этого не видела, потому что сравнивала строки уже без
окончаний. Теперь чтение и запись побайтовые, а файл, который нельзя подвинуть
построчно, отклоняется целиком — вместе с остальными семью, чтобы отказ не
оставлял дерево наполовину поднятым.

Release notes инструмент не пишет: они говорят, **что** изменилось.

### Проверка утечки называет инвариант, а не инцидент

> ⚠️ **Уточнение из 3.7.16:** утверждение ниже про «один вердикт» двух файлов
> сказано слишком сильно — у сторожа есть список имён-заглушек, которого нет в
> сборке, и верное свойство — вложение (сборка строже). Подробности — в
> поправке к нотам 3.7.15 выше.

В v2.23.0 абсолютный путь раннера CI — вместе с именем приватного репозитория —
попал в каждую собранную команду. Сторож против этого **перечислял два литерала**
того инцидента, а значит приватное имя обязано было лежать в `tools/convert.py`,
и этот файл **уезжает в публичное зеркало**.

Теперь правило говорит то, что на самом деле охраняет: в собранной команде не
должно быть абсолютного пути **с чьей-либо машины**. Приватное имя из файла
исчезло полностью, а покрытие **выросло** — ловится и путь с ноутбука

## [3.7.11] - 2026-09-09

**Установка рантайм-скриптов в проект под GigaCode стала одной строкой вместо
составной команды с `rm -rf` внутри.**

### Одна строка вместо трёх, и её труднее выполнить неправильно

Под GigaCode рантайм-скрипты обязаны лежать в самом проекте — защита файловой
системы не даёт исполнять их из каталога установки расширения. Перенос делает
человек: команда, в аргументах которой назван защищённый каталог, отклоняется до
запуска, и по той же причине этого не может сделать за вас агент.

Раньше это была составная команда, у которой три способа не сработать. Забыли
`rm -rf` — `cp -R` при существующем каталоге кладёт копию **внутрь**, и вместо
скриптов получается вложенный каталог, а проверка падает с неочевидным
диагнозом. Забыли повторить после обновления плагина — в проекте остаётся
прошлая версия. Ошиблись путём до архива — копируется не то, и молча.

Теперь в архиве расширения лежит `setup-project.sh`, и из корня проекта
запускается одна строка:

```bash
bash ~/.gigacode/extensions/polisade/setup-project.sh
```

Скрипт берёт файлы от собственного расположения — подставлять путь не нужно.
Сносит прежнюю копию перед записью и копирует **содержимое**, так что вложенный
каталог невозможен по построению, а не по внимательности. Годится и для первой
установки, и для каждого обновления: та же строка. Сверяет результат с
`MANIFEST.sha256` и печатает, что сделал — версию плагина, каталог, число
сверенных файлов. Любое расхождение — ненулевой код возврата и имя файла,
который не сошёлся.

И два отказа, которые важнее удобства: скрипт не работает вне корня проекта
(иначе `rm -rf` внутри действовал бы в случайном каталоге) и не работает, если
его запустить изнутри каталога установки — там он скопировал бы расширение в
самоё себя, а следующий запуск снёс бы исходники.

Инструкция в руководстве сжалась с абзаца до строки. `/polisade:doctor` и
`/polisade:init-verify` печатают её же, когда копии нет или она устарела — но
только если каталог тот, что по умолчанию: проект, который держит копию в своём
`POLISADE_SCRIPTS_ROOT`, по-прежнему получает явную команду копирования, потому
что скрипт всегда пишет `.polisade/bin`.

Остальных сборок это не касается: вендорит скрипты только GigaCode.

## [3.7.10] - 2026-09-09

**Открытый PR не теряется из-за регистра, память проекта снова доезжает до
репозитория, ревью не обещает изоляции, которой нет, спека с ключом трекера не
теряется при поиске, а HTML-комментарий в теле чека не съедает файл приёмки.**
Пять независимых дефектов; общее у них одно — каждый тихо отменял ровно то
поведение, которое инструмент про себя заявлял.

### Провенанс PR в Bitbucket не зависит от регистра

Последствия были два, оба тихие. На пути проверки lookup отвечал «открытого PR
для ветки нет» с полной уверенностью, и оператору сообщали, что записанный в
конфигурации PR, похоже, закрыт, — при живом открытом PR. На пути `pr-create`
тот же дефект открывал ДУБЛЬ поверх живого PR.

Сверка происхождения переведена на единственную пару функций: одна читает и
типизирует `fromRef.repository`, вторая сравнивает ключ проекта и slug
без учёта ASCII-регистра с обеих сторон. Обе точки сверки — поиск открытого PR и
идентити-запрос `pr-list --head` — идут через них; других сверок ПРОИСХОЖДЕНИЯ
репозитория в клиенте не осталось (сравнения веток, базы, хоста и SHA —
отдельные и остаются точными). Это закреплено сторожем в регрессии, который
разбирает AST клиента: он ловит синтаксические формы прямого сравнения
идентификаторов вне общей функции — не семантику, и обход через переименование
в промежуточную переменную ему не виден.

Нормализация — ASCII-only, а не `casefold()`: Unicode-свёртка many-to-one
(`ſ` → `s`, `K KELVIN SIGN` → `k`, `ß` → `ss`), и на ней чужой репозиторий с
похожим неASCII-написанием ключа был бы признан своим — оба круга ревью
показали это на `ACMEſVC`. Ключи и slug'и Bitbucket ASCII, поэтому сужение
ничего не теряет, а неоднозначное написание остаётся несовпадением
(fail-closed: клиент создаёт PR, а не выдаёт чужой за свой).

Нормализация применяется ТОЛЬКО к сравнению: REST-пути и веб-URL для оператора
по-прежнему несут написание из `origin`. **Ветки не тронуты** — git-рефы
регистрозависимы, `feat/X` и `feat/x` остаются разными ветками. Чужие
репозитории остаются чужими: контрольные случаи проверяют другой проект, форк
и ключи, которые лишь похожи (префикс, надстрока, отличие в один символ).

Попутно выровнена вторая точка сверки: идентити-запрос `pr-list --head` считал
нечитаемое происхождение молчаливым несовпадением, а не выброшенной записью —
ровно та форма, из которой выходит недоказанный пустой ответ, который
потребитель читает как «PR ещё нет». Теперь обе точки соблюдают контракт
выпуска 3.7.9: пустой ответ только доказанный.

Поведение GitHub-пути не изменено. Регрессия — сценарий A, герметичный, с
фикстурой, несущей асимметрию регистра живого инцидента (URL клона в нижнем
регистре, ответ фейкового сервера — в верхнем):
`bash scripts/regression_tests.sh --ops=vcs_provenance`.

### `knowledge.json` перестал быть локальным файлом

`/polisade:init` клал в `.gitignore` пару строк — исключить `.state/` целиком и
вернуть обратно `knowledge.json`. Вторая строка **никогда не работала**: git не
заходит внутрь исключённого каталога, поэтому возврат файла из него недостижим.
Стек, команда тестов, паттерны и договорённости оставались у того, кто их
сгенерировал: коллега и вторая машина заполняли всё заново. Обходного пути не
было — скилл прямо запрещает `git add -f` на эти файлы.

Правило записано формой, которая исключает каждую **запись**, а не каталог:
каталог остаётся просматриваемым, и возврат срабатывает. Одного шаблона мало —
битое правило лежит у всех, кто прошёл `init` раньше, поэтому `/polisade:migrate`
чинит его отдельной идемпотентной миграцией. Проект, который игнорирует `.state/`
целиком и ничего не просит назад, не трогается: он не сломан, и переписывать его
правило значило бы изменить то, о чём он просил.

Заодно ужесточено, чего миграции `.gitignore` делать не должны, — и это касается
не только новой, но и двух прежних. Файл, который оказался символической ссылкой,
больше не переписывается: следовать за ней значит писать за пределы проекта.
Файл без прав на запись отклоняется **до** составления плана, а не роняет
применение на середине. Правило, которое всё равно не заработает — когда строка
возврата стоит после исключения или ниже есть ещё одно `.state/` — не
переписывается вовсе: чинить его нечем, а объявлять починку, которой не было,
хуже, чем не трогать. Каждый такой отказ **называется** в отчёте вместе с
причиной. И переводы строк остаются как есть: правка одного правила больше не
переписывает весь файл на репозитории, выкаченном под Windows.

### Ревью описывает режим, в котором действительно работает

`/polisade:review` утверждал, что Codex-ревьюер запускается в изолированной
песочнице только на чтение, а вызывал его автономным режимом с правом записи в
рабочем каталоге. Утверждение об изоляции — ровно то, что читает человек,
решающий, пускать ли инструмент в закрытый контур; расхождение обнаруживается за
минуту. Текст приведён к коду: ревьюер автономен, сам выбирает, что прочитать, и
ограничить этот выбор нельзя. Линт теперь не даёт разойтись снова — и сработает с
той стороны, которую правят, если однажды решено будет наоборот перевести вызов
на настоящий read-only.

### Спека с ключом внешнего трекера находится поиском

С версии 3.7.5 имя спеки может нести ключ задачи: `SPEC-001__ABC-1234__slug.md`.
Защита от перезаписи искала совпадение по имени с дефисом сразу после номера,
такого файла не находила и молча пропускала перезапись. Тот же просчёт нашёлся
уровнем глубже и оказался тяжелее: подсчёт следующего свободного ID **не считал**
такие файлы за спеки, то есть мог выдать номер, который уже занят. Сплошной прогон по этому классу нашёл его ещё в двух местах, и уже в
поставляемом коде: сверка счётчиков в `/polisade:sync` и в `/polisade:doctor`
не считала такие файлы за спеки — а именно разбор ИМЕНИ работает тогда, когда
у файла испорчен или отсутствует заголовок, то есть подстраховки там нет по
построению. Все места теперь сравнивают по префиксу идентификатора, принимая
оба разделителя, и по-прежнему не путают `SPEC-1` с `SPEC-10`.

### Комментарий в теле чека остаётся текстом команды

Разборщик файла приёмки проверял «мы внутри HTML-комментария» раньше, чем «мы
внутри блока кода». Проверка, чья команда содержит `<!--` — например поиск
комментариев в собранной вёрстке, — уводила разбор до ближайшего `-->` и съедала
не только свою пару, но и все следующие: файл приёмки терялся целиком. Внутри
блока кода содержимое теперь читается как текст чека. Пара, спрятанная в
комментарий **снаружи** блока, по-прежнему не исполняется: рендер markdown её не
показывает, значит ратифицировать её никто не мог.

## [3.7.9] - 2026-09-08

**Открытие PR больше не спотыкается на ответе сервера: пустота отличается от
непрочитанного, PR в другую базу — не «тот же самый», проигранная гонка
возвращает победителя, а флаг перед подкомандой не сбрасывается.** Выпуск
чинит пять дефектов клиента `polisade_vcs.py`, найденных адверсарным ревью
идемпотентного `pr-create`. Все они дают отказ там, где PR открылся бы — или,
хуже, тихо выдают чужой PR за свой. Вместе с ними — починка мигратора по
внешнему сообщению об ошибке: испорченная запись состояния больше не роняет
прогон трейсбеком, а называется.

### Ответ сервера разбирается в одном месте, и «не смог прочитать» — не «нет PR»

Каждая точка чтения списка `values` делала это по-своему: `{"values": null}`
(так отвечают инстансы за плагином или прокси) роняло цикл, а словарь или
строка на месте списка читались как пустая страница — то есть как
доказанное «открытого PR нет». Теперь разбор один, и он различает три исхода:
здоровая страница, непригодный контейнер, и страница, у которой пришлось
выбросить записи. Непригодные записи — не словарь, без `id`, с `fromRef: null`,
с репозиторием строкой — **считаются**, а не отбрасываются молча: страница,
из которой что-то выпало, больше не заявляет, что ветку проверили.

### PR в другую базу — это другой PR

Поиск существующего PR сравнивал только ветку-источник. Открытый PR той же
ветки, нацеленный в другую базу, подхватывался как «уже существующий», и
вызывающая сторона получала ссылку на PR, который вольётся не туда. Теперь
совпадением считается пара «источник + база», а PR той же головы в другую базу
уезжает отдельным полем `other_base` — он виден, но не выдаётся за свой.

### Список PR по ветке — это запрос тождества, а не перечень

`pr-list --head` — путь, которым потребитель решает «PR уже есть». Он отдавал
первую запись какой угодно: PR из чужого форка с тем же именем ветки и PR в
другую базу читались как свои, и их ссылка уезжала в задачу. Теперь при
`--head` применяются те же проверки, что и в поиске перед созданием:
происхождение обязано совпасть, а с новым флагом `--base` — и база. Каждая
запись несёт `baseRefName`, чтобы потребитель мог судить сам. Без `--head`
команда остаётся перечнем репозитория, где PR из форка **к нам** — законный
участник.

### Проигранная гонка возвращает победителя, а не отказ

Поиск и создание не атомарны: два вызова подряд (повтор после сбоя, дважды
нажатая кнопка) оба видят пустоту и оба создают. Проигравший получал от
сервера отказ «такой PR уже есть» и падал. Замок здесь невозможен — сервер
единственная точка сериализации, — поэтому клиент делает повторный поиск и
возвращает найденный PR как существующий, с пометкой `race_resolved`.

### Глобальный флаг перед подкомандой больше не сбрасывается

`--project-root X whoami` заканчивался с `project_root="."`: argparse
разбирает подкоманду в свежее пространство имён и переносит его поверх
основного вместе с умолчаниями. Значение, разобранное до подкоманды, молча
затиралось, и операция шла против текущего каталога, а не против переданного.
Теперь умолчания живут ровно в одном месте, и значение до подкоманды
действует так же, как после неё.

### Мигратор не падает на записи состояния, которую не смог прочитать

`/polisade:migrate` умирал необработанным `KeyError: 'path'` — и в режиме
предпросмотра, и при применении. Падение случалось **до** того, как план был
посчитан, так что нельзя было даже посмотреть, что миграция собиралась
сделать. Хватало одной записи `ADR-*` в `artifactIndex` без строкового поля
`path`.

Причина — страж, который читается как проверка, но ею не является:
`isinstance(v.get("path", ""), str)` пропускает запись, у которой ключа нет
вовсе (пустая строка — тоже строка), а следующая строка обращается к ключу
напрямую. Таких мест было два, и второе опаснее первого: оно живёт в шаге
переноса ADR, то есть роняло **применение в середине**. Второе было затенено
первым, поэтому починка одного места перенесла бы падение, а не убрала его.

Теперь обе точки читают запись через один защитный читатель, а сама запись не
пропускается молча: мигратор называет её координату в `pm_questions` и
советует пересобрать индекс через `/polisade:sync` — тот же контракт, по
которому уже сообщаются отказы примитива записи корпуса. Заодно перестали
теряться записи, где `path` есть, но это не строка: раньше их молча
игнорировали.

Чужой ключ вместо `path` синонимом **не** признаётся. Схема индекса —
`{status, path}`, и ни одна выпущенная версия не писала ничего другого, так
что выдуманное поле сообщается, а не принимается: мигратор, который считает
испорченное состояние нормой, перестаёт быть местом, где о поломке узнают.

Чужой ключ синонимом не признаётся, но и рядом с ним прибрано. Состояние,
собранное по памяти вместо чтения файла, кривое обычно не в одном поле, поэтому
чинить только сообщённое означало бы оставить того же человека падать на
следующем. Сплошной прогон по кривым состояниям — 246 форм в обоих режимах —
нашёл тот же класс отказа ещё в семи местах: строка вместо объекта в
`settings`; блок `artifactIndex`, присутствующий со значением `null`; запись
артефакта, которая сама не объект; кривой блок `architecture`, роняющий уже
**применение** (проверка типа стояла в расчёте плана, но не в его исполнении);
`schemaVersion` не числом; блок `permissions` в `.claude/settings.json`, который
роняет уже дописывание разрешений; и файл, который целиком не объект — валидный
JSON, но не документ состояния — включая формы, на которых разбор JSON отказывает не
синтаксической ошибкой: глубокая вложенность и очень длинный числовой литерал.
Ни одно из них больше не роняет прогон.

Теперь мигратор доходит до плана и называет каждую запись, которую не смог
прочитать, — с советом, который подходит именно её блоку: `/polisade:sync`
пересобирает `artifactIndex` сканом диска, но устаревшего блока `artifacts` не
касается, и обещать обратное значило бы отправить человека к команде, которая
чинит половину сказанного. Замена целого блока называется в плане отдельно от
заполнения недостающего ключа — это видно **до** применения. А файл, который
вовсе не документ состояния, получает честный отказ тем же голосом, каким
мигратор уже отвечал на битый JSON.

### Совместимость

Формат ответов JSON расширен, но не изменён: поля `lookup_reason`,
`lookup_base`, `skipped`, `other_base`, `race_resolved`, `files_skipped`,
`visible_projects_ok` **добавлены**; существующие поля и их типы прежние,
`pr-list` по-прежнему отвечает массивом, `--help` не изменился. На здоровом
ответе сервера потребитель, который новых полей не читает, работает как
раньше. На **испорченном** ответе поведение меняется намеренно: там, где
`pr-list` раньше отдавал пустой массив с кодом 0, теперь код 1 и причина в
stderr — пустой список читается потребителем как «PR нет» и ведёт ровно к
тому дублю, от которого защищает идемпотентность.

## [3.7.8] - 2026-09-07

**Проверка настроек стала честнее: маска не обходится, нечитаемый файл не
выдаётся за чистый, настоящие команды не помечаются мусором.** Выпуск
исправляет три дефекта, найденных вторым кругом ревью предыдущей версии.

### Маска идентификатора не обходится написанием пути

Путь пользователя маскировался только в канонической форме. Написание с
повторными слэшами маску обходило, и числовой идентификатор учётной записи
попадал в отчёт целиком — в обоих режимах вывода. Это ровно то, от чего
проверка и защищает. Теперь маскируется нормализованный путь, и числовой
сегмент закрывается везде, где встречается.

### Файл, который не удалось прочитать, больше не «чистый»

При отказе доступа, битом JSON или неожиданной структуре файл молча
пропускался, и проверка сообщала «мусора нет». Теперь она честно говорит, что
файл **не просканирован**, и называет причину. «Есть мусор» и «не смог
прочитать» — разные сообщения. Попутно чтение перестало быть неограниченным:
нерегулярные файлы пропускаются, размер ограничен.

### Настоящие команды не помечаются мусором

Правило для `open` — реального инструмента macOS — считало его обрывком кода,
противореча собственной таблице команд. Такие же ложные тревоги были на
закавыченных командах, подоболочках и печатающих командах с текстом в
аргументе. Правила пересобраны с приоритетом точности: на замерном файле
**девятнадцать находок и ни одного ложного срабатывания**. Цена сужения
названа прямо в коде — одиночное закавыченное слово в находки больше не
попадает.

## [3.7.7] - 2026-09-07

**Проверка состояния проекта стала внимательнее к настройкам разрешений, а
честный отказ — точнее.** Небольшой выпуск: он собирает три улучшения,
найденные при разборе поведения плагина в закрытом корпоративном контуре.

### Проверка настроек видит оба слоя

Некоторые CLI-агенты, разбирая составную shell-команду, записывают в свои
настройки бесполезные правила-разрешения — обрывки команд и даже строки
чужого кода. `/polisade:doctor` умел это замечать, но искал только в файле
настроек **внутри проекта**. Настройки уровня пользователя оставались вне
поля зрения, а мусор копится обычно именно там: проверка печатала «чисто» при
трёх десятках мусорных правил.

Теперь проверяются оба слоя, и в выводе видно, какой файл чистить. Путь
пользовательского файла при этом маскируется: в корпоративных системах он
содержит числовой идентификатор учётной записи, а его утечка — ровно то, о
чём эта же проверка предупреждает. Рамка предупреждений разведена: файл
проекта не должен уехать в коммит, пользовательский чистится у себя.
Проверка по-прежнему **советует, а не блокирует**.

### Детектор мусора видит обрывки кода, а не только команд

Раньше опознавались три вида мусора: ключевые слова shell, битые пути и пути
с числовым идентификатором. Целый класс проходил мимо — многострочный код,
распавшийся построчно и осевший в разрешениях как «команды»: обращения к
атрибутам, вызовы стандартной библиотеки, ключевые слова языка, голые
строковые литералы.

Теперь этот класс опознаётся, каждый вид со своей пометкой. На реальном файле
из корпоративной среды — двадцать две находки вместо двух, **при нуле ложных
срабатываний**: настоящие правила вроде запуска интерпретатора или команд
системы контроля версий находками не считаются.

### Честный отказ называет ещё одну форму

Когда вызов проверочного скрипта отклонён, команда обязана остановиться и
процитировать отказ дословно, а не пересказывать по исходнику, что скрипт
«сделал бы». Список узнаваемых формулировок пополнен отказом модели
разрешений агента — той формой, которой отказ приходит в закрытом контуре
чаще всего. Изменение доведено до всех сборок, включая сборки для слабых
моделей.

### ⚠️ Уточнение к выпуску 3.7.6

Заметки 3.7.6 объясняли, что защита файловой системы отклоняет команду **по
её тексту**, если в аргументах назван каталог установки расширения. Замеры в
живом корпоративном контуре этого не подтвердили: путевого отказа не
наблюдалось, а чтение файла из каталога установки прошло штатно.

Отказ приходит от **модели разрешений агента** — списка разрешённых команд с
запретом по умолчанию. Контрольная проверка в одной сессии: скрипт из корня
проекта выполняется, тот же интерпретатор с путём в каталог установки —
отказ. Единственная разница — где лежит скрипт.

**Решение 3.7.6 при этом верно и подтверждено замером.** Перенос скриптов в
проект создаёт ровно ту разницу, которая отделяет разрешённый вызов от
отклонённого. Неверным было объяснение причины, а не сам фикс.

## [3.7.6] - 2026-09-06

> ⚠️ **Уточнение из 3.7.7:** объяснение механизма ниже («отказ выносится по
> ТЕКСТУ команды») замерами в живом контуре **не подтверждено** — отказ
> приходит от модели разрешений агента. Само решение верно и подтверждено
> контрольной проверкой. Подробности — в записи 3.7.7 выше.

**Сборка для GigaCode CLI стала отдельной целью конвертера, а рантайм-скрипты
плагина переехали в проект.** Накопительный выпуск: он собирает изменения
девяти предыдущих итераций, которые вышли без отдельных версий.

### Скрипты плагина — в проекте (`.polisade/bin`)

В GigaCode CLI каталог установки расширения закрыт для чтения и запуска, и
отказ выносится по ТЕКСТУ команды: вызов вида `python3
<каталог-установки>/scripts/X.py` отклоняется ещё до запуска. Раньше это
обходили только для чтения шаблонов; сами вызовы скриптов оставались нерабочими
— а на них держится весь цикл PR / sync / migrate.

Теперь для сборки GigaCode рантайм-скрипты живут в **коммитируемой копии
внутри проекта** — `.polisade/bin/`, — а команды зовут их как
`${POLISADE_SCRIPTS_ROOT:-.polisade/bin}/<script>.py`. Защищённого пути в
тексте команды нет, файлы физически вне каталога установки.

Копию переносит человек, один раз, из обычного терминала:

```bash
mkdir -p .polisade
cp -R <распакованный архив расширения>/scripts .polisade/bin
git add .polisade/bin && git commit -m "chore: vendor polisade runtime scripts"
```

дальше её получает вся команда через git. **При обновлении плагина шаг нужно
повторить** (сначала `rm -rf .polisade/bin`).

Копия проверяемая. В архиве расширения лежит `scripts/MANIFEST.sha256` — версия
плагина плюс sha256 каждого файла; он копируется вместе со скриптами.
`/polisade:init` не начинает работу, пока копии нет, а `/polisade:doctor`
(проверка `scripts_vendor`) и `/polisade:init-verify` сверяют её с манифестом:
пропавший или изменённый файл — «копия устарела или искажена» с готовой
командой обновления, манифест от другой версии — предупреждение. Отличие только
в переводе строки (CRLF после checkout'а на Windows) — отдельное
предупреждение с причиной, а не «искажена»: содержимое то же. Права на файлы не
проверяются — хэш считается по байтам.

Границу называем прямо: закрыт класс **запуска** скриптов. Чтения справочных
файлов из каталога установки (гайды `/polisade:design`) остаются как были.

Технически это стало возможно потому, что GigaCode теперь **полноценная цель**
`tools/convert.py --target gigacode`: переименование, которое раньше жило
sed-блоком в релизном пайплайне, переехало в конвертер, а регрессия сравнивает
результат нового пути со старым байт-в-байт.

### Провайдер VCS по умолчанию зависит от сборки

В сборке GigaCode `settings.vcsProvider` по умолчанию — `bitbucket-server`, и
шаг «выбери провайдера» в `/polisade:init` больше не задаёт вопрос: в этой
инсталляции GitHub недоступен по сети, ответ всегда один, а ошибочный выбор
ломал первый же `/polisade:implement`. `/polisade:doctor` предупреждает, если
такой проект всё же настроен на `github`. Для Claude Code, Qwen CLI и opencode
всё осталось прежним: `github` и вопрос PM.

### Честные отказы вместо выдуманных результатов

Когда вызов скрипта отклонён средой, команда обязана **остановиться** и
процитировать отказ дословно, а не пересказывать по исходнику, что скрипт
«сделал бы», не собирать dry-run вручную и не переписывать скрипт во временную
копию: такая копия не байт-идентична, и набор применённых изменений меняется
молча. То же правило теперь стоит перед каждым push и созданием PR — при
недоступности штатного помощника команда останавливается и докладывает, а не
пробует `git push` напрямую. `/polisade:migrate` дополнительно проверяет сам
себя (`--self-check`).

### Детерминированный интерпретатор

Все поставляемые команды зовут Python как `${POLISADE_PYTHON:-python3}`.
Поведение на macOS и Linux не меняется. На Windows, где установщик python.org
не создаёт алиас `python3`, достаточно один раз выставить `POLISADE_PYTHON`
(например, `py -3`) — и агенту больше нечего искать по машине.
`/polisade:doctor` показывает выбранный интерпретатор и его версию.

### Гигиена VCS и состояния

`pr-create` идемпотентен: если открытый pull request по ветке уже есть, он
возвращается вместо создания дубля. Запись файлов состояния атомарна (временный
файл + `os.replace`), словарь статусов и переходов вынесен в один модуль для
всех команд, а `/polisade:init` ставит git-хук `pre-push`, запрещающий push в
`main`/`master` без явного разрешения.

### Гейты проекта: команда решает, плагин докладывает

Проект может объявить свои команды-гейты, и `/polisade:implement` зовёт их в
нужный момент цикла. В этом выпуске их четыре: **security-скан**,
**API-совместимость**, **миграционный тест** и **perf-верификация NFR**. Общий
контракт один и намеренно узкий — по **коду выхода**: команда сама решает, на
каком пороге ей падать (`bandit -ll`, `semgrep --error --severity ERROR`,
`oasdiff breaking --fail-on ERR`, свой `pytest -m migration`), а плагин её
запускает, различает пять исходов и честно пишет результат в описание pull
request'а. Отдельного поля «уровень серьёзности» нет — его роль играют флаги
самого инструмента и режим `block` / `warn`.

Ключевое в контракте — что **не** считается находкой: инструмент не найден
(код 127) и команда не уложилась в таймаут. Оба исхода докладываются как есть и
никогда не блокируют: отсутствующий сканер не должен выглядеть как чистый скан,
а зависший — как проваленный. Хвост вывода попадает в описание PR как данные:
ограждения кода в нём обезвреживаются, иначе вывод инструмента закрыл бы цитату
и остаток описания поехал бы.

Границу называем прямо: команда проекта исполняется тем же шеллом и с тем же
уровнем доверия, что `testCommand` — это не песочница. И конвейер прячет код
выхода (`scanner | tee` завершается кодом `tee`), так что `pipefail` — забота
самой команды.

### Ревью тестов стало проверяемым

Оценка «Тесты: X/10» распалась на четыре подкритерия — покрытие критериев
приёмки, edge cases, поведение против структуры, надёжность — с итогом-средним
и явным списком антипаттернов. Рубрика одинакова во всех сборках плагина.

Её поддерживает советующий сканер диффа: он показывает `файл:строка` для
тест-антипаттернов (`sleep`, тест без единого утверждения, только снапшот,
порядковая зависимость, недетерминированное время) и для **стендозависимых
значений** — DSN с хостом, имена схем и стендов, hostnames, IP, порты,
абсолютные локальные пути. Сканер всегда завершается успешно и ничего не
блокирует: решение принимает ревьюер, скрипт только показывает места. Его
слепые пятна перечислены в `--help`. Соответствующие пункты появились и в
self-review, и в шаблоне проектного файла правил.

### Диаграммы и схема БД: детерминированные линты

Новый линт Mermaid ловит класс ошибок, из-за которых диаграмма не
отрисовывается, — но честно называет себя детектором известных граблей, а не
парсером Mermaid: зелёный вердикт означает «известных граблей нет», а не
«рендерится». Легальные формы (`;` внутри кавычек, комментарии, ER-кардинальности)
исключены явно. Линт встроен в проверку дизайна, в подготовку архитектурных
документов и в шаблон CI.

Сверка ER-модели с кодом перестала сравнивать одни имена: колонка стала записью
из типа, длины, `nullable` и `default`, плюс отдельная находка на расхождение
ORM-модели с миграцией. Есть таблица нормализации типов и её переопределение в
конфиге; поле сравнивается только когда его видят обе стороны. Оценок скрипт
по-прежнему не ставит.

### Практики API и БД

Рубрика HTTP-проверок закрывает знакомый класс «прогнал smoke, получил 500,
написал „всё работает 🎉“»: `2xx` — успех, `4xx` — успех только против
контракта, `5xx` — провал, таймаут — провал инфраструктуры. Исключение для
`5xx` ровно одно и его нужно предъявить: статус описан в `5xx`-секции
контракта и на неё дана ссылка. Выдумывать ожидаемый статус при отсутствии
контракта запрещено. При любом провале итог
«всё работает» недопустим, а раздел «Failing requests» обязателен.

Дисциплина починки расхождений код↔БД зафиксирована: направление всегда
источник-истины → миграция → код, прямой DDL мимо migration-tool запрещён, и
шаг не продолжается без заполненного решения из шести полей в файле задачи.
Автоматического детектора выполненных DDL нет и не планировалось — клиент не
стоит между агентом и базой, и такой детектор был бы обещанием, которого он не
держит.

### Правила команды и сверка с эталоном

В шаблон проекта добавлен слот для правил команды — каркас `docs/conventions/`
из пяти разделов, без языка и фреймворка, плюс указатель на него в базе знаний.
Плагин правила **не сочиняет и не проверяет**: он перечисляет файлы механически
и даёт их ревьюеру и self-review. Указатель ограничен корнем проекта, а
сломанный указатель отличается от «правил нет» — раньше это было одно и то же.

Отдельный инструмент сверяет поля спецификации с **эталоном, который передал
пользователь** (JSON Schema, OpenAPI, AsyncAPI, блоки в Markdown), и печатает
таблицу расхождений. Это линт формата на входе, а не вердикт о документации
проекта. YAML разбирается подмножеством, и при неразборе результат — честная
ошибка с координатой файла, а не «расхождений нет».

### Инфраструктура

Все GitHub Actions подняты на мажоры с нативным Node 24. Подсказка об установке
Codex CLI приведена к одной форме (npm или brew) во всех командах, где она
встречается.

## [3.7.5] - 2026-08-26

**Спека получает ключ задачи внешнего трекера — и получает его в ИМЕНИ
файла.** Внешние SDD-проверки читают diff pull request'а как список **путей**:
им нужно решить «в этом PR есть спецификация, и она относится вон к той задаче
трекера», не открывая файлов. До сих пор `/polisade:spec` собирал имя как
`SPEC-NNN-<slug>.md`, где slug — kebab-case из заголовка: внутренний ID
Polisade в пути был, ключ внешней задачи — нет.

Релиз добавляет `/polisade:spec --story=<KEY>`: ключ валидируется, попадает в
имя файла отдельным полем `__<KEY>__` и записывается во frontmatter
(`story:`):

```
docs/specs/SPEC-001__ABC-1234__payment-gateway.md
```

Двойные подчёркивания — не украшение, а **механический разделитель двух
форм**. Slug всегда строчный kebab-case, поэтому `__` в нём не встречается
никогда — формы различаются по символу, а не по договорённости. Одиночного
дефиса не хватает: заголовок «Postgres 15 upgrade» даёт keyless-имя
`SPEC-001-postgres-15-upgrade.md`, из которого regex «первый сегмент после ID»
извлёк бы `postgres-15` и связал спеку с несуществующей задачей. С `__`
keyless-имя не матчится вовсе — ошибка становится «связь не найдена» (видно),
а не «связь найдена не та» (тихо и неверно).

Ничего не мигрируется: если ключа нет ни в флаге, ни у родительского
PRD/FEAT, имя прежнее, существующие спеки остаются как есть, и внешняя
проверка их не свяжет.

Честно о границе: это соглашение, а не барьер. Клиент **производит** имя по
контракту и отказывается класть в ключ то, что ключом не является, — но
проверяет его только на входе, и человек по-прежнему может переименовать файл
руками. Поэтому ключ дублируется во frontmatter: имя — то, что видит внешняя
проверка, frontmatter — то, что переживает переименование.

### Добавлено

- **Флаг `--story=<KEY>` у `/polisade:spec`** (принимается и форма
  `--story <KEY>`). Ключ проходит валидацию `^[A-Za-z][A-Za-z0-9]*-\d+$`;
  при несовпадении — аборт до генерации спеки. Отсутствие флага, пустая
  строка, `null`, `~`, `none` трактуются одинаково — как отсутствие ключа.
- **Отказ принимать собственный ID Polisade как ключ трекера** — полный
  список типов (`PRD, SPEC, PLAN, TASK, FEAT, BUG, DEBT, ADR, CHORE, SPIKE,
  DESIGN, ARCHRUN`), сравнение регистронезависимое. Внешний экстрактор видит
  `ABC-1234` и `SPIKE-5` одинаково, значит отказ обязан стоять на стороне
  производителя имени.
- **Наследование от родителя.** Если флаг не передан, ключ берётся из
  `story:` во frontmatter родительского PRD/FEAT. Поле `story: null` добавлено
  в шаблоны PRD и Feature Brief. Следствие: у PRD с заполненным `story:` спека
  получит keyed-имя и БЕЗ флага.
- **Поле `story:` в обоих шаблонах спеки** (`spec-template.md` и
  `change-spec-template.md`). Значение по умолчанию — `null`.
- **Контракт имени и регулярное выражение извлечения опубликованы** в
  `docs/framework-usage-guide.md` — внешнюю проверку пишет не автор спеки.

### Изменено

- **Write-guard глобит по ID-префиксу** (`docs/specs/SPEC-{N}-*.md`) вместо
  сравнения с точным именем. С переменным сегментом точное имя заранее не
  известно, и прежняя проверка перестала бы ловить коллизии ID.
- **Пути к файлу спеки больше нигде не реконструируются по шаблону** —
  change-spec-линт и шаблоны вывода команды берут фактический путь, а backlink
  в design-референсе переведён на ссылку по ID (`[[SPEC-XXX]]`). Собранное по
  шаблону имя расходилось с реальным на любой спеке без ключа.

## [3.7.4] - 2026-08-21

**«Живой корпус пишет один исполнитель» — теперь проверяемое свойство, а не
фраза.** Единый примитив записи корпуса (`scripts/polisade_corpus_io.py`)
появился в 3.7.1, но в продукте оставались писатели мимо него: ADR из
`/polisade:design` и `/polisade:spike` ложились в `docs/architecture/decisions/`
обычным Write, а мигратор переносил туда старые ADR через `rename`. Обещание
было верным про один скилл и неверным про продукт. Релиз переводит оставшихся
писателей на примитив, ставит на это сканер и переносит сверку цели ВНУТРЬ
примитива, вплотную к записи.

Честно о границе: сканер состоит из инвентаря (каждый файл поставляемой
поверхности, называющий `docs/architecture`, обязан быть классифицирован —
писатель через примитив, названное исключение или читатель) и растяжки (поиск
самой записи мимо примитива). Инвентарь обойти нельзя, не тронув реестр;
растяжку — можно: она не видит путь, отмытый через конфиг или сборку из
частей, а в прозе читает строку, а не смысл. Исключений ровно два, у обоих
напечатаны область и причина: `/polisade:design` пишет legacy-пакет
`DESIGN-NNN-<slug>/` (этот уклад устарел и сворачивается мигратором) и
`/polisade:init` создаёт пустое дерево корпуса при инициализации проекта
(корпуса, блокировки и журнала на тот момент ещё нет).

### Добавлено

- **Хэш-контракт примитива.** Вызывающий объявляет, каким он ВИДЕЛ цель, а
  примитив проверяет это сам, вплотную к записи и под блокировкой операции:
  - `write … --expect-absent` — файла быть не должно; на POSIX публикация идёт
    атомарным `linkat`, то есть решение «имя свободно» принимает ядро и окна
    между проверкой и записью не существует вовсе;
  - `write … --expect-sha256 <hex>` — у существующего файла должны быть именно
    эти байты; ключ берётся из прочитанных байтов, а не из размера, даты или
    пути, и перед самой публикацией тождество файла сверяется повторно. Честно
    о силе: это надёжный **детектор** правки, сделанной до финальной сверки, а
    не барьер против писателя, работающего ровно в момент публикации —
    условного переименования в POSIX нет. Безоговорочно атомарен только
    `--expect-absent`;
  - `promote … --expect-from <json>` — карта ожиданий для записей и удалений
    плана, `--expect-strict` требует ожидания для каждого пути;
  - отчёт печатает, сколько путей реально прикрыто контрактом, а сколько нет:
    «мы задали ожидания» невозможно прочитать как «всё сверено».
- **Инвентарь писателей корпуса** — `python3 scripts/polisade_lint_skills.py .
  --corpus-writers` печатает роли всех файлов, называющих корпус, вместе с
  областью и причиной каждого исключения.
- **Публикация ADR через примитив** в `/polisade:design`: артефакты решения
  собираются во временном каталоге, ревью идёт там же, а в корпус они
  попадают одним вызовом с `--expect-absent` — занятый номер теперь честный
  отказ, а не перезапись чужого решения.

### Изменено

- Мигратор переносит старые ADR в корпус через примитив, снимая исходную
  копию только после того, как байты доказанно на месте: обрыв оставляет
  дубль, а не дыру. Если примитив отказал (корпус занят другим прогоном,
  прошлая промоция оборвана, цель занята) — шаг не делает ничего, а причина
  печатается вместе с кодом и подсказкой, а не теряется.
- `/polisade:spike` кладёт ADR в корпус тем же вызовом с `--expect-absent`.
- Расхождение хэш-контракта в `promote` отказывает до резервной копии и до
  открытия журнала, поэтому корректный отказ больше не помечает проект как
  «промоция оборвана».

## [3.7.3] - 2026-08-21

**Сверка «архитектура ↔ код» — теперь честная по устройству.** Команда
`/polisade:reconcile-docs` существовала, но её вывод читался как вердикт
(«соответствует»), а согласие человека запускало автоматическое обновление
дизайн-документов с коммитом — мимо единого примитива записи корпуса и без
подтверждения по каждому пункту. Команда переустроена вокруг двух разделённых
вещей: механической **разрешимости ссылок** и **мнения модели** о
расхождениях.

Честно о границе: расхождения находит **модель**, а не скрипт. Пустой список
означает «модель ничего не заметила», а не «архитектура соответствует коду», —
и это напечатано в каждом выводе. Детерминированно проверяется только то, что
механически проверяемо: существует ли файл, на который ссылается корпус,
попадает ли диапазон строк в его размер, встречается ли символ. Это факт о
**ссылке**, а не о верности утверждения: разрешившаяся ссылка ничего не
доказывает, неразрешившаяся ничего не опровергает — файл могли переименовать.
Вердикт сверки с провенансом `CONFIRMED` и блокирующими проверками остаётся
свойством платного продукта, см.
[`docs/what-works-without-paid-parts.md`](docs/what-works-without-paid-parts.md).

  заявляют привязку к коду и разрешается ли каждая ссылка — нет файла, не
  найден символ, строки вне файла, путь вне репозитория), `record` (приём
  расхождений модели: проверка **формы** — координата, класс из закрытого
  словаря, названная уверенность, существующий адрес в корпусе — и отчёт
  `.state/reconcile-report.json`), `template` (канонический вход на вымышленном

- Честная рамка в **каждом** выводе — текстовом и в JSON-поле `frame`, включая
  вывод-отказ: мнение, а не вердикт; проверяется разрешимость ссылки;

  синоним), **отвергается**, и отчёт при этом не пишется. Мнение не выдаёт
  себе гарантию записью в JSON.
- Проверка самого промпта сверки: он обрамлён маркерами и линтуется — на
  посторонние идентификаторы из внешних наборов задач (список терминов
  читается с диска, а не переписан в код проверки — иначе она была бы
  константно-зелёной), на сохранность обязательных запретов (только чтение,
  запрет вердикта, обязательная координата, названная уверенность, пункт
  «работай только с файлами этого репозитория») и на абсолютные пути.

### Изменено

- `/polisade:reconcile-docs` переписана целиком: рамка в начале и в каждом
  выводе; сверка идёт по живому корпусу (срез по спеке читается из её
  changeset и trace, старый пакет — переходным чтением вслух); чтение кода —

  `docs/` до и после и останавливается, если дерево изменилось, — но это

### Закрыто внутренним адверсарным ревью

Первая редакция держала обещания только на счастливом пути. Закрыто здесь же:
подменённый ссылкой каталог `.state` больше не может превратить отчёт в запись
в корпус (путь проходится по компонентам, ссылка отвергается); отказ от полей
вердикта не обходится ни вложением, ни переименованием ключа, ни значением
(схема расхождения закрыта, сравнение нормализовано); `show` больше не
пересказывает произвольный файл отчёта, а перепроверяет его той же схемой и
подставляет каноническую рамку; рамка появилась на всех путях отказа (ошибка
вызова, неверный корень, нечитаемый вход, отсутствующий отчёт), а
`template --json` печатает чистый вход для `record`; исчез ложный «ссылка
разрешилась» (каталог не координата, символ ищется внутри заявленных строк,
лишние части координаты не отбрасываются молча); адрес в корпусе проверяется
разрешением пути, а не префиксом строки; inline-комментарии и кавычки в
frontmatter разбираются, незакрытый блок сообщается, чтение — строгий UTF-8.

Второй круг закрыл остаток: отчёт больше не может оказаться внутри
объявленного корпуса (пересечение каталогов отвергается до записи); спуск к
каталогу отчёта идёт по закреплённым дескрипторам с непредсказуемым временным
именем, а там, где платформа этого не умеет, режим назван слабее прямо в коде —
песочницы у бесплатной линии нет, и это не скрывается; показ последнего отчёта
собирает ответ заново из перепроверенных расхождений, поэтому чужие поля
верхнего уровня перечисляются только по именам и не приезжают читателю под
нашей рамкой; адрес расхождения вне корпуса стал ошибкой, а не
предупреждением; рамка появилась и на `--help`; у детекта правок названы
границы — он видит итоговое состояние `docs/` (снимок по содержимому файлов),
не ловит правку с откатом и не говорит, кто правил.

Третий заход ревью закрыл разбор координат (пустая или лишняя часть больше не
отбрасывается молча, цифрами считаются только обычные цифры, путь с двоеточием
в имени разбирается), показ отчёта (инструмент принимает собственный отчёт и
краснеет на чужих полях верхнего уровня), обход корпуса (нечитаемый подкаталог
больше не выглядит пустым корпусом, а каталог-который-файл — честная ошибка),
вердикт на другом языке и за эмодзи, заимствование чужого штампа провенанса из
файла корпуса, а также проверку промпта: добавлены формы, отменяющие запреты
изнутри, и честно сужено описание — это порог из ключевых слов, а не
смысловой аудит.

## [3.7.2] - 2026-08-20

**Пакет `docs/architecture/DESIGN-NNN-<slug>/` перестаёт быть вторым источником
правды.** Архитектурные артефакты жили двумя укладами — старый пакет на каждую
спеку и живой корпус `docs/architecture/`; команды читали то одно, то другое, и
читали молча. Новый инструмент переводит пакет на корпус, а команды теперь
объявляют переходное чтение пакета вслух.

Честно о границе: инструмент — **транспорт и карта, а не конвертер**. Он
переносит байт-в-байт только то, у чего дом в корпусе — тот же одиночный файл,
и по действующей раскладке корпуса **таких артефактов сегодня нет ни одного**:
C4-уровни живут как типизированный источник плюс рендер, остальное — «один ко
многим» и/или типизировано. Поэтому реальная миграция — это полная карта домов
с контрольными суммами, пометка пакета как legacy и список того, что должна
свернуть модель; сама свёртка (термины по файлу на термин, ER в типизированные
сущности, диаграммы в потоки и жизненные циклы, контракты) — синтез фактов, и
инструмент его не подменяет. Смысловых коллизий он не видит: что тот же термин
уже описан в корпусе другими словами — не его знание. Обещание «пишет только
через один примитив» относится к этому инструменту, а не ко всему продукту:
записи ADR из других команд идут прежним путём.

### Добавлено

- `scripts/polisade_migrate_silo.py` — перевод пакета на живой корпус,
  stdlib-only. Dry-run по умолчанию, запись — явным `--apply`, и вся запись
  идёт через тот же примитив `polisade_corpus_io.py`. Повторный прогон — no-op
  (сравниваются байты цели, а не её наличие). Конфликт (цель существует и
  отличается) по умолчанию останавливает прогон целиком и печатает вопросник —
  разрешает его человек (`--on-conflict=stop|skip|overwrite`, `--only`), а не
  скрипт. План и запись идут под одной блокировкой, и прямо перед записью
  сверяются байты и цели, и источника — файл, сдвинутый между планом и записью,
  останавливает прогон, а не перезаписывается молча. Перезапись без резервной
  копии запрещена. Нечитаемое поддерево пакета — отказ, а не пробел в карте.
  Из пакета не удаляется ничего. Файл, которого нет в каталоге
  артефактов, называется вслух, а не пропускается. Список того, что должна
  свернуть модель, выдаётся машинно (`--worklist`).
- `MIGRATED.md` в пакете — карта домов (файл → дом в корпусе → `sha256`) и
  явная фраза «источник правды — корпус». Файл, который ещё не свёрнут в
  корпус, карта помечает отдельно: его единственная копия по-прежнему в пакете,
  и читать его нужно оттуда.

### Изменено

- Команды-читатели переведены на корпус: сначала факт ищется в корпусе, и
  только затем в пакете; чтение пакета объявляется отдельной строкой в выводе.
- `/polisade:design-corpus` описывает, как забрать список несвёрнутых файлов и
  на каких правилах складывать их в типизированные дома.

## [2.25.0] - 2026-05-27

**`/pdlc:tasks` reference content is now delivered reliably under GigaCode's
Filesystem Guard — no failed install-directory reads and nothing reconstructed
from memory.**

Under GigaCode CLI, moving the heavy prompt blocks of `/pdlc:tasks` into
`references/` for just-in-time reading did not work: the install directory is
read-protected by the Filesystem Guard, so every reference read was denied and
the weak model silently reconstructed the content from context (the same
anti-pattern the v2.24.x init work addressed). The fix delivers the canonical
reference content with deterministic build-time code instead of a runtime read:

- The bytes of every `/pdlc:tasks` reference file are inlined into the command
  itself when the Qwen/GigaCode bundle is built (between sentinel markers), and
  the runtime "read this reference" directives are rewritten to point at that
  inlined block with an explicit "do not reconstruct" instruction.
- A strict build gate refuses to ship if the command — or the emitted
  `pdlc-tasks` Agent Skill — still references the install-directory reference
  path or keeps a live runtime read directive.
- The install-dir reference audit (`pdlc_lint_skills.py --audit-install-refs`)
  now surfaces reference-read dependencies as a distinct class.

Under Claude Code (no Filesystem Guard) behaviour is unchanged. Corporate
validation on GigaCode CLI 26.4.11: `/pdlc:tasks` reads the canonical
step-content with no Guard-denied reads and produces canonical TASK files.
This is the delivery foundation; compressing the remaining heavy skills
(`implement`, `design`) to a single delivered step is the next step.

## [2.24.2] - 2026-05-25

**`/pdlc:init` now ships as an auto-discoverable Agent Skill (`pdlc-init`),
`.env` is no longer written through the tool layer under GigaCode's
Filesystem Guard, and a clean-context verify sub-agent was added.**

Follow-up to the v2.24.1 Filesystem-Guard work, after corporate validation on
GigaCode CLI surfaced a partial failure. Three root causes, all closed:

1. **`init` was not emitted as an Agent Skill.** Under GigaCode, `/pdlc:init`
   resolved to a skill named `pdlc-init` that did not exist (only the other
   13 skills were emitted), so the model never received the inline-embedded
   canonical templates and fell back to reading the read-protected install
   directory — then silently reconstructed broken state (a `PROJECT_STATE.json`
   missing `pdlcVersion`/`schemaVersion`, a placeholder `.env.example`).
   **Fix:** `init` and the new `init-verify` are now in the emit-as-skill
   allowlist, so GigaCode loads `pdlc-init`/`pdlc-init-verify` as Agent Skills
   and gets the inline bytes directly. The strict build additionally verifies
   the emitted `pdlc-init` skill carries the canonical inline content and
   contains no `.env` write path.
2. **The Filesystem Guard hard-denies a tool-layer write to `.env`.** **Fix:**
   `/pdlc:init` now creates only `.env.example` (which the Guard allows) and
   prints an explicit instruction for the PM to create `.env` manually via
   `cp .env.example .env`. The inline `.env` block was removed from the
   converter, and the strict build guards against its return.
3. **Weak models reconstruct instead of reading.** **Fix:** a new `init-verify`
   skill runs a Guard-safe deterministic check over the target-project files
   only (valid `.state/*.json`, correct `pdlcVersion`/`schemaVersion`, a
   provider-conditional `.env.example` check). `/pdlc:init` invokes it in a
   clean-context sub-agent and STOPs without printing the success banner on
   failure.

The auto-discoverable-skill allowlist grew from 13 to 15 (`init` +
`init-verify`).

## [2.24.1] - 2026-05-08

**`/pdlc:init` and the `/pdlc:migrate` bitbucket-server bootstrap no longer
depend on reading the plugin install directory (GigaCode Filesystem Guard).**

Under GigaCode CLI, a fresh `/pdlc:init` produced a broken project: a
`PROJECT_STATE.json` with an invented `version` field (no
`pdlcVersion`/`schemaVersion`), a garbled context file, a truncated
`.env.example`, and an altered `knowledge.json`. Root cause: the Filesystem
Guard read-protects the plugin install directory, while the init step
instructed the agent to Read each template then Write it. Under the Guard the
Read fails and a weak model silently reconstructs the content from memory. The
same problem affected the Python migration helper, which read the
`.env.example` template directly from disk.

**Changes (patch bump — only the content-delivery mechanism changes; no
schema/field changes):**

- The init algorithm now carries an explicit "do not reconstruct, paraphrase,
  regenerate, or improve" invariant plus sentinel markers for convert-time
  auto-embed. The Claude Code build keeps its Read+Write flow (no Guard there).
- The converter inlines the exact canonical bytes of every template into the
  converted `init` command between the markers and rewrites the copy step into
  a Write-only, exact-bytes list. The strict build checks that no install-dir
  reference remains, that the inline `pdlcVersion` matches the manifest, and
  that the shipped migration script carries a byte-identical canonical
  `.env.example` literal.
- The migration script now uses a module-level canonical `.env.example`
  literal instead of reading it from disk.
- New lints enforce the inline markers and the byte-identity of the migration
  literal; a new audit flag catalogs skills that read the install directory.
- A new repository invariant: skills and scripts that initialize or migrate
  target-project state must not depend on reading their install directory
  under the Qwen/GigaCode build.

All version-lockstep sources synchronized to 2.24.1.

## [2.22.1] - 2026-04-24

**Composite requirement ID scoping.** FR/NFR references
across documents now use `{DOC_ID}.{REQ_ID}` — e.g. `PRD-001.FR-007`,
`FEAT-002.FR-007`, `SPEC-002.NFR-003`. Bare `FR-007` remains valid only
as implicit scope of the artifact's parent document, and only when a
single top-level doc declares the id. Cross-doc bare references to
collidable ids are blocked by lint and fixed automatically by
`/pdlc:migrate --apply`.

### Почему

В проекте с несколькими top-level requirement documents (PRD + несколько
FEAT по версиям + несколько SPEC) один и тот же номер `FR-007` может
быть объявлен в каждом из них как разное требование. Bare `FR-007`
становится globally ambiguous, а команды вида «удали FR-07 и все ссылки
на него» превращаются в минное поле: `grep -r 'FR-07' .` ловит
совпадения в чужих документах и может снести не то. Composite ID
делает cross-doc ссылки самодостаточными, lint ловит остаточные bare
коллизии на CI, doctor показывает warning в матрице.

### Что изменилось

- **Lint** (`pdlc_lint_artifacts.py`) — проверяет TASK `requirements`,
  ADR `addresses`, DESIGN `manifest.yaml`
  `artifacts[].realizes_requirements` и frontmatter sub-artifact файлов.
  Ambiguous bare ref → error (exit=1). Legacy 2-digit (`FR-07`) →
  warning с подсказкой `/pdlc:migrate --apply`. Drift между manifest и
  sub-artifact (включая missing-field кейс) → error.
- **Doctor** (`pdlc_doctor.py --traceability`) — матрица теперь строится
  по всем top-level documents (PRD/SPEC/FEAT), а не только SPEC.
  Requirement IDs отображаются как composite (`PRD-001.FR-007` vs
  `FEAT-002.FR-007` никогда не сливаются). Добавлен `ambiguous_refs`
  warning surface — **non-blocking** (exit code по-прежнему определяется
  только `uncovered`).
- **Migrate** (`pdlc_migrate.py`) — schema v4 → v5. Новая миграция
  `OPS-026` работает в один проход: (a) канонизирует `FR-07` →
  `FR-007` в headings PRD/SPEC/FEAT + frontmatter-ссылках, (b) для
  ambiguous bare refs проставляет scope-prefix через parent chain
  (TASK → PLAN.parent, ADR → related, DESIGN sub-artifact →
  manifest.parent). Префикс присоединяется **только** когда
  резолвленный parent doc действительно объявляет это требование —
  иначе ref остаётся bare, без прилепления случайного scope
  (защита от порчи данных). Идемпотентна.
- **Templates** — `task-template.md`, `adr-template.md`,
  `design-package-template.md`, `spec-template.md` обновлены на
  composite формат. В `CLAUDE.md` добавлена секция
  «Requirement ID Scoping» с guard-rule **«не делай `grep -r FR-NNN`»**.

### Breaking change для JSON consumers `--traceability`

Root формата `pdlc_doctor.py --traceability --format=json` сменился с
bare array `[...]` на объект `{"matrix": [...], "ambiguous_refs": [...]}`.

Миграция для скриптов:

```python
# До 2.22.1:
data = json.load(r)
for entry in data: ...

# С 2.22.1:
data = json.load(r)
for entry in data["matrix"]: ...
# опционально читайте data["ambiguous_refs"] для PM-warning
```

Text / md форматы получили **aдитивную** секцию «AMBIGUOUS REFERENCES
DETECTED» перед матрицей — парсинг существующих markdown-таблиц не
ломается. Внутри `matrix[]` поля entries расширились (добавлен
`full_id` к каждому requirement, plus `doc_id`/`doc_kind` на верхнем
уровне entry).

### Миграция для существующих проектов

```bash
# 1. dry-run — покажет список изменений
python3 scripts/pdlc_migrate.py .

# 2. применить — канонизация + backfill composite prefix
python3 scripts/pdlc_migrate.py . --apply --yes

# 3. убедиться что линт зелёный
python3 scripts/pdlc_lint_artifacts.py .

# 4. PM-матрица по всем top-level docs
python3 scripts/pdlc_doctor.py . --traceability
```

Миграция идемпотентна — повторный запуск no-op. Unresolved refs (bare
на коллидирующий id, parent chain не найден либо резолвленный parent
не объявляет id) печатаются в stderr как warning; файлы не трогаются,
нужен ручной фикс.

## [2.20.5] - 2026-04-22

### Fixes
- `scripts/regression_tests.sh :: test_ops_023` — portable mtime/content
  check. The original `stat -f '%m' ... || stat -c '%Y' ...` works on
  BSD/macOS but `stat -f` on GNU coreutils (Linux CI) prints filesystem
  info with `rc=0` and never hands off to the fallback, so the

  with a stdlib `python3 -c 'hashlib.sha256(...)'` content-hash probe —
  byte-exact, behaves identically on Linux and macOS.

  `spec`, `roadmap`, `design`, `tasks`) — dropped the `{plugin_root}/` prefix

  double-substitution (`${PDLC_PLUGIN_ROOT:-…}//abs/...`) that `tools/validate.py`

  already used by `skills/design/SKILL.md` when referencing its own `references/`.
