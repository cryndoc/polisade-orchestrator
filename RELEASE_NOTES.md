# История выпусков

Краткая история опубликованных версий Polisade Orchestrator. Описания отражают состояние соответствующего выпуска; текущие команды и ограничения приведены в [README](README.md) и [руководстве пользователя](https://cryndoc.github.io/polisade-orchestrator/).

До версии 3.0 команды имели префикс `/pdlc:*`. В актуальных сборках используется `/polisade:*`, а в opencode — `/polisade-*`.

## [3.8.17] - 2026-10-16

- Уточнены инструкции самостоятельной сборки для Qwen, GigaCode и opencode; Claude Code использует исходный формат плагина.
- Перед публикацией дополнительно проверяются готовые архивы, текст релиза и HTML-руководство. Версии сборок, файлы с номером версии и без него должны совпадать.
- Руководство и ссылки на скачивание закреплены на версии 3.8.17. Поведение команд не изменилось.

## [3.8.16] - 2026-10-16

- Руководство опубликовано на GitHub Pages и включено в каждый релиз как автономный HTML-файл. README содержит краткий старт и ссылки на подробные разделы.
- Уточнены установка GigaCode, хранение состояния в git и поведение ревью. Улучшены читаемость, навигация и отображение таблиц на узких экранах.
- История выпусков сокращена до опубликованных версий. Проверка публикации охватывает все документы, шаблоны и комментарии поставляемых скриптов.
- Уточнены границы записи архитектурного корпуса: проверка хешей работает как детектор изменений, а не как распределённая блокировка.
- Имена SPEC с ключом задачи — соглашение, а не барьер. Форма без ключа применяется, только если ключа нет ни в флаге, ни у родительского брифа.

## [3.8.15] - 2026-10-12

- Тесты PR запускает инструмент проверки задачи до независимого ревью. Ревьюер получает подтверждённые результаты и задание в отдельном файле.
- Добавлены проверки актуальности результатов после изменений в дереве задачи. Для GigaCode после обновления необходимо обновить проектную копию `.polisade/bin`.

## [3.8.14] - 2026-10-11

- Инструмент подготавливает рабочее дерево задачи и проверяет основную ветку перед реализацией и отправкой изменений.
- Статус задачи читается и сохраняется в её рабочем дереве; подтверждённый merge завершает задачу через общий VCS-инструмент.

## [3.8.13] - 2026-10-10

- Итог слияния и дальнейшие действия формирует VCS-инструмент.
- Уточнены имя сборки GigaCode и допустимые формы команд оболочки; отправка изменений и финальный коммит используют штатные помощники.

## [3.8.12] - 2026-10-08

- Слияние после ревью во всех сборках выполняется через общий VCS-инструмент.
- Отказ слияния сохраняется в состоянии задачи; повтор требует решения человека. Отчёт сохраняется в файл.

## [3.8.11] - 2026-10-07

- Опубликованы накопленные исправления обработки вопросов к человеку, отменённых задач и проверки удалённых веток.
- `design-corpus` доступен во всех четырёх сборках; режим остаётся экспериментальным и включается явно.
- Проверка спецификации сообщает о требованиях, не покрытых разделом трассировки. Отчёты для пользователя формирует инструмент.

## [3.8.7] - 2026-09-15

- Диагностика сборщика больше не включается в постоянные инструкции агента.

## [3.8.6] - 2026-09-15

- Исправлены инструкции обновления: агент не должен удалять действующие файлы проекта из-за диагностического сообщения.

## [3.8.5] - 2026-09-15

- Изменение экспериментальных режимов направляется через `migrate`, без ручного редактирования служебного JSON.

## [3.8.4] - 2026-09-15

- `state` корректно распознаёт существующий набор приёмочных проверок.

## [3.8.3] - 2026-09-15

- Числа в отчёте миграции вычисляет скрипт; модель не должна восстанавливать их по тексту.

## [3.8.2] - 2026-09-15

- Исправлена доставка шаблонов документов для Qwen и opencode.

## [3.8.1] - 2026-09-15

- В опубликованной документации реальные идентификаторы окружения заменены учебными примерами.

## [3.8.0] - 2026-09-15

- Уточнены правила команд оболочки GigaCode, доставка проектных скриптов и пути миграции.
- Исправлены обработка занятого имени ветки и диагностика файлов Python bytecode. `init` сохраняет исключения Git для общего состояния проекта.

## [3.7.22] - 2026-09-11

- Линтер корректно разбирает комментарии в шаблонах и не принимает их за значения полей.

## [3.7.21] - 2026-09-11

- Исправлены границы записи при нумерации артефактов, нумерация DESIGN-пакетов и обновление связанных ссылок.
- Усилены проверки состояния и состава файлов, которые должны попасть в коммит.

## [3.7.20] - 2026-09-10

- Справочники форматов архитектуры включаются в проектную копию скриптов.
- Сгенерированные документы требуют проверки человеком; доступность файлов не означает подтверждённое качество содержимого.

## [3.7.19] - 2026-09-10

- Журнал сессий хранится в Git как отдельные файлы, названные по постоянному идентификатору сессии.
- Уточнены перенос журнала в рабочие деревья и поведение миграции.

## [3.7.18] - 2026-09-10

- `sync` документирует и выводит результаты нумерации артефактов.

## [3.7.17] - 2026-09-10

- Команды создания артефактов используют постоянное семя; номера назначает `sync --apply` на основной ветке.
- При нумерации обновляются машинные ссылки между артефактами.

## [3.7.16] - 2026-09-10

- Введены две стадии идентификации: постоянное семя при создании и номер после объединения на основной ветке.
- Семя сохраняется после нумерации, чтобы прежние ссылки оставались разрешимыми.

## [3.7.15] - 2026-09-10

- База приёмки включена в общее состояние репозитория.
- Добавлен единый инструмент обновления версии и уточнена диагностика публикации.

## [3.7.14] - 2026-09-09

- Исправлены ссылки на файлы, отсутствующие в публикуемом составе проекта.

## [3.7.13] - 2026-09-09

- Справочник описывает, какие файлы состояния сохраняются в Git, и ограничения доступности архитектурного корпуса на момент выпуска. Текущие возможности описаны в README.

## [3.7.12] - 2026-09-09

- Установка скриптов GigaCode в проект выполняется через `setup-project.sh` с проверкой состава файлов.

## [3.7.10] - 2026-09-09

- Поиск PR в Bitbucket учитывает регистр имён; `knowledge.json` включён в общее состояние Git.
- Исправлены поиск спецификаций с ключом трекера и разбор HTML-комментариев в файле приёмки. Уточнён фактический режим ревью.

## [3.7.9] - 2026-09-09

- При работе с PR различаются отсутствие результата и ошибка чтения сервера.
- Поиск учитывает целевую ветку; повторное создание при гонке возвращает уже созданный PR.

## [3.7.8] - 2026-09-07

- Усилены проверка путей настроек, обработка нечитаемых файлов и распознавание допустимых команд.

## [3.7.7] - 2026-09-07

- Диагностика проверяет оба слоя настроек разрешений и точнее объясняет отказ выполнения.

## [3.7.6] - 2026-09-07

- Скрипты плагина для GigaCode доставляются в проектный каталог `.polisade/bin`.
- Провайдер VCS по умолчанию зависит от сборки. Отказы выполнения сообщаются пользователю без подмены результатом, восстановленным по исходнику.

## [3.7.5] - 2026-08-26

- `spec --story=<KEY>` сохраняет ключ задачи трекера в имени файла спецификации и в её frontmatter.
- Обновлены способы записи документов архитектуры через единый инструмент.

## [3.7.3] - 2026-08-21

- Сверка архитектуры с кодом представлена как best-effort отчёт о возможных расхождениях, требующих проверки человеком. Автоматическое применение изменений отключено.
- Обновлены запись общего архитектурного корпуса `docs/architecture/` и перенос существующих DESIGN-пакетов.

## [3.7.0] - 2026-08-14

- Добавлена команда `acceptance`: запись намерения человека, запуск связанных проверок и исправление кода по их результатам.
- Хеши позволяют обнаруживать изменение проверок относительно сохранённой базы, но не запрещают редактирование файла.

## [3.6.2] - 2026-08-12

- Подготовлен самостоятельный комплект установки и обновлены инструкции для поддерживаемых CLI.
- Архитектурный корпус остаётся опциональным; классический формат спецификации сохранён по умолчанию.

## [3.2.0] - 2026-06-23

- Обновлены основные команды разработки, форматы состояния и экспериментальные возможности архитектурного корпуса. Существующие проекты сохраняют совместимость через миграцию.

## [3.1.2] - 2026-06-21

- Устранены дополнительные ошибки без изменений схемы состояния и набора команд.

## [3.1.1] - 2026-06-21

## [3.0.1] - 2026-06-18

## [2.25.0] - 2026-05-27

- Уточнена безопасная запись конфигурации окружения в сборках с ограничениями файлового доступа.

## [2.23.2] - 2026-04-24

## [2.21.1] - 2026-04-24

## [2.21.0] - 2026-04-23

## [2.20.10] - 2026-04-23
